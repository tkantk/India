# Namaste India — Plan 2: The Grand Tour

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A child opens the site, taps once, presses a big play button, and is taken on a 2 minute 41 second narrated journey through India — with the words lighting up as they are spoken, states glowing in time, the camera flying to Delhi, and a tiger that growls.

**Architecture:** A React 19 app over the data Plan 1 generated. One Web Audio engine lives outside React entirely and drives everything: it plays a clip, fires cues off the audio clock, and publishes the current word. The map is a three-layer SVG stack whose camera is a CSS transform on an **HTML** wrapper — never on an SVG group, which WebKit cannot composite. Cue verbs are dispatched through one registry, so adding a beat is data, not code.

**Tech Stack:** React 19.2, Vite 8, TypeScript 7, `motion` 13.1.1 (imported from `motion/react`), `react-router-dom` 7 with HashRouter, Vitest 4. No new runtime dependencies.

## Global Constraints

Every task's requirements implicitly include this section. These values were verified against WebKit source, Apple and W3C documentation, and the installed packages — do not substitute alternatives from memory.

### Platform

- **Node 23+, ESM.** Scripts are `.mjs`; app code is `.ts`/`.tsx`.
- **`erasableSyntaxOnly` is on**, so TypeScript constructs that emit code are banned: no `enum`, no `namespace`, and **no constructor parameter properties** (`constructor(private ctx: AudioContext)`). Declare the field and assign it in the body.
- **Node types are scoped to a test-only tsconfig project.** Do not use `process`, `Buffer` or `node:*` in `src/`.
- **Vite `base` is `'./'` and routing MUST be `HashRouter`.** Mixing `'./'` with `BrowserRouter` breaks deep links in production only — it passes local testing and fails live.
- **Never write a leading-slash asset path.** Always `assetUrl(...)` from `src/lib/assetUrl.ts`.
- **No runtime network calls.** Every asset is bundled. No analytics, no third-party scripts, no fonts from a CDN.

### Rendering — the rules that keep an old iPad smooth

The target is an iPad Air 2 / 5th-gen iPad: A8X or A9, 2 GB RAM, 60 Hz. Budget **8 ms of your own work per frame**, because SVG rasterisation and the compositing commit both land on the main thread in WebKit's legacy SVG engine.

- **Never transform an SVG `<g>` and never animate `viewBox` frame by frame.** `LegacyRenderSVGModelObject` derives from `RenderElement`, not `RenderLayerModelObject`, so SVG children can never own a compositor layer. A `<g>` transform repaints all 36 paths on the main thread every frame; a `viewBox` change additionally forces layout and evicts cached resource buffers.
- **The camera is a CSS transform on an HTML wrapper `<div>`, then a commit.** Animate `transform` for 350–450 ms, and on completion set the SVG's `viewBox` to the target rect and reset the transform to identity in the same frame.
- **`will-change: transform` on an SVG child is a no-op.** It only promotes elements that can own a RenderLayer. On the wrapper div it works — but a full-screen composited layer costs about 12.6 MB on a 2048×1536 iPad, so add and remove it around the animation rather than leaving it on.
- **No SVG `<filter>` anywhere.** WebKit blurs on the CPU in three passes; `feDropShadow` has been a known performance cliff since 2012. A glow is a CSS `drop-shadow()` shorthand, and it must be the **last** filter operation or WebKit refuses to composite it.
- **Highlighting toggles a class on a cached node reference**, from a `Map<string, SVGPathElement>` built once. Not React state, not a per-path `onClick`. Transition `fill` only.
- **`opacity` on an SVG child is not composited either** — it is a software repaint exactly like `fill`. The usual "animate opacity, it's free" advice does not transfer.
- **Hit testing uses a separate invisible layer** with `fill="none" stroke="none" pointer-events="fill"`. `pointer-events: fill` sets `canHitStroke=false`, which skips `CGPathCreateStrokedPath` — the expensive half of the test. Safari has no spatial index for SVG hit testing and is roughly 80× slower than Chrome at it.

### Touch and children

- **Touch targets are 104 CSS pixels.** Nielsen Norman Group recommends 2cm × 2cm for children under nine, which is 104px on a 264 ppi iPad. Apple's 44pt is 8.5mm there — below even the adult ergonomic minimum. The *visible* control may be smaller; the tappable area may not.
- **Every control carries a word, not only a symbol.** Only 2% of children's apps follow this and children genuinely cannot reliably read a pause glyph.
- **Body text for a child expected to read it is 24px.** Contrast targets WCAG AAA (7:1), not the 4.5:1 AA floor.
- **`touch-action: manipulation`** on every interactive element: it removes the 350 ms tap delay at all zoom scales and disables double-tap zoom. `user-scalable=no` does **not** work — Safari has ignored it since iOS 10.
- **Reserve a 28px dead gutter** on the left and right edges. The system back-swipe cannot be intercepted from a web page.

### Audio

- **Unlock synchronously inside a real `touchend`/`click`/`keydown` handler**, before any `await`. A `canplaythrough` handler does not count.
- **Set `navigator.audioSession.type = 'playback'`** in that same handler, feature-detected. Without it, Web Audio routes to the ringer channel and an iPad with sound off plays nothing. This is the highest-severity user-facing failure available.
- **One `AudioContext` for the whole app**, module-scoped, never closed on route change. Safari caps a page at about four.
- **There is no API to detect a muted iPad.** Every narrated moment must also be visible, and the start screen must confirm the child heard something.
- **Evict decoded buffers** beyond the current and next clip. Decoded PCM is roughly 24× the compressed size, and exhausting memory kills the tab with no catchable error.

Three states: `idle` → `checking` → done. `unlock` and `playTestSound` are injected so the test never touches Web Audio.

```tsx
import { useState } from 'react'

type Props = {
  onReady: () => void
  unlock: () => Promise<void>
  playTestSound: () => Promise<void>
}

export function StartGate({ onReady, unlock, playTestSound }: Props) {
  const [phase, setPhase] = useState<'idle' | 'checking' | 'silent'>('idle')

  async function begin() {
    // MUST run before the first await: WebKit only honours the gesture for
    // synchronous work started inside the handler.
    await unlock()
    setPhase('checking')
    await playTestSound()
  }

  if (phase === 'idle') {
    return (
      <main className="gate">
        <h1>Namaste!</h1>
        <p>Shall we go and see India?</p>
        <button className="tap begin" onClick={begin}>Tap here to begin</button>
      </main>
    )
  }

  return (
    <main className="gate">
      <h1>Did you hear that?</h1>
      <div className="row">
        <button className="tap" onClick={onReady}>Yes, I heard it</button>
        <button className="tap" onClick={() => setPhase('silent')}>No, it was quiet</button>
      </div>
      {phase === 'silent' && (
        <>
          {/* No web API can read the iPad's mute state, so words are the cure. */}
          <p className="help">
            Turn the volume up, and check the sound is not switched off in
            Control Centre. Then try again.
          </p>
          <button className="tap" onClick={() => { setPhase('checking'); void playTestSound() }}>
            Try again
          </button>
        </>
      )}
    </main>
  )
}
```

**Design constraints carried from research — every one of these has a reason:**

- Position comes from `offset + (ctx.currentTime - startedAt) * rate`, read in a `requestAnimationFrame` loop. Never from `HTMLAudioElement.currentTime` (Firefox quantises it to 2 ms by default and 100 ms under resistFingerprinting) and never from `performance.now()` or accumulated rAF deltas, which drift against the audio hardware clock over a 60-second clip.
- Cues fire from a **monotonic cursor advanced by a `while` loop**, not a `find`. If one frame runs long — GC, layout — several cues fall due at once and all of them must fire, in order.
- Ducking uses `GainNode.linearRampToValueAtTime`. `HTMLMediaElement.volume` is a hard no-op on iOS: Apple's own docs say it "is not settable in JavaScript. Reading the volume property always returns 1."
- `AudioBufferSourceNode` is one-shot. Pause, resume, replay and rate change are all "create a fresh node and `start(0, offset)`".
- Null `source.onended` **before** calling `stop()`, or the stop triggers the ended handler and re-enters the finish logic during a seek.
- The `slower` button uses `playbackRate = 0.85`. `AudioBufferSourceNode.playbackRate` has no pitch correction, so this drops the pitch about 2.8 semitones — acceptable for a playful children's voice, and the alternative (a second pre-rendered slow track) doubles the paid render. Do not go below 0.8.
- Handle the iOS `"interrupted"` state: listen for `statechange` and `visibilitychange`, call `resume()` on foreground, and if the state is still not `running`, surface a visible tap-to-continue rather than leaving a child staring at a page that stopped talking.
- Wrap every `decodeAudioData` — it rejects with a bare, message-less `EncodingError` on some browsers. A single bad asset must degrade to "no sound for this clip", never a dead page.
- Keep at most the current and next clip decoded.

The constructor takes a context so tests can inject a fake; production uses the module singleton at the bottom. `tick()` is public so the test can step the loop by hand.

Write it to satisfy the contract in the Interfaces block above and the constraints listed under it. Key shapes:

```ts
export class Narrator {
  constructor(private ctx: AudioContext) {
    this.master = ctx.createGain(); this.master.connect(ctx.destination)
    this.narr = ctx.createGain(); this.narr.connect(this.master)
    this.amb  = ctx.createGain(); this.amb.connect(this.master)
    this.fx   = ctx.createGain(); this.fx.connect(this.master)
    this.amb.gain.value = FULL
  }

  /** MUST be called synchronously inside a click/touchend/keydown handler. */
  async unlock() {
    const session = (navigator as unknown as { audioSession?: { type: string } }).audioSession
    // Since iOS 17. Without it, Web Audio uses the ringer channel and an iPad
    // with sound switched off plays absolutely nothing.
    if (session) session.type = 'playback'
    const s = this.ctx.createBufferSource()
    s.buffer = this.ctx.createBuffer(1, 1, this.ctx.sampleRate)
    s.connect(this.ctx.destination); s.start(0)
    if (this.ctx.state !== 'running') await this.ctx.resume()
  }

  get position() {
    return this.src ? this.offset + (this.ctx.currentTime - this.startedAt) * this.rate : this.offset
  }

  /** Public so tests can step it; production drives it from rAF. */
  tick = () => {
    const p = this.position
    // A while loop, not a find: a long frame can make several cues due at once
    // and every one must still fire, in order.
    while (this.cursor < this.cues.length && this.cues[this.cursor].t <= p) {
      this.onCue(this.cues[this.cursor++])
    }
    let w = this.word
    while (w + 1 < this.starts.length && this.starts[w + 1] <= p) w++
    if (w !== this.word) { this.word = w; this.emit() }
    if (this.src && typeof requestAnimationFrame === 'function') this.raf = requestAnimationFrame(this.tick)
  }
}

const DUCK = 0.18, FULL = 0.7, RAMP = 0.25

let engine: Narrator | null = null
export function getNarrator(): Narrator {
  if (!engine) {
    const AC = window.AudioContext ?? (window as unknown as { webkitAudioContext: typeof AudioContext }).webkitAudioContext
    engine = new Narrator(new AC({ latencyHint: 'interactive' }))
  }
  return engine
}
```

A module-scoped singleton is required, not a `useRef` or a Context: React StrictMode mounts, unmounts and remounts every component in development, so a `useEffect` creating an `AudioContext` runs twice and its cleanup closes the first. The symptom looks exactly like an iOS unlock bug and is not one. Safari also caps a page at about four contexts.

Add a dev-mode assertion that the constructor runs at most once.

## Task 5: The map — three-layer stack and hit testing

**Files:**
- Create: `scripts/build-hitlayer.mjs`, `src/map/MapStage.tsx`, `src/map/useMapNodes.ts`, `src/map/map.css`
- Test: `scripts/build-hitlayer.test.mjs`, `src/map/useMapNodes.test.ts`
- Generates: `src/data/hit.json`

**Interfaces:**
- Consumes `src/data/geo.json`.
- Produces:
  - `src/data/hit.json` — `{ places: Record<slug, { d: string; pin: [number, number] }> }`, where `d` is a heavily simplified path and `pin` is a fallback circle centre for states too thin to hit reliably.
  - `useMapNodes(): MapApi` where
    ```ts
    type MapApi = {
      nodes: Map<string, SVGPathElement>
      highlight(slug: string, on: boolean): void
      /** Staggered wave. Used by highlightAllStates / highlightUnionTerritories. */
      highlightMany(slugs: string[], staggerMs?: number): void
      clear(): void
    }
    ```
  - `<MapStage onPick={(slug: string) => void} />`

**The three layers, in DOM order:**

1. `<div class="stage">` — an **HTML** box. The only element that is ever transformed.
2. `<svg class="base">` — the 36 visible paths, `pointer-events: none` on the
   *group*, NOT on the `<svg>` element, and NOT on `.hit`. This distinction is
   load-bearing and was got wrong once: with `pointer-events: none` on `.hit`
   itself, a tap hitting no child falls straight through to `svg.base` below,
   so a listener on `.hit` never fires. Measured over 4,278 real misses in a
   browser: zero reached the handler, silently disabling near-miss snapping
   while every unit test still passed.

   **jsdom cannot catch this.** It performs no hit testing, so a test that
   dispatches `pointerdown` directly on an element asserts only that the
   handler works *when called* — never that it is ever called. Any claim about
   which element receives a tap must be checked in a real browser, or at
   minimum by asserting the `pointer-events` values against the element that
   actually hosts the listener.
3. `<svg class="hit">` — the simplified paths plus a `<circle r="22">` pin for every small state, all `fill="none" stroke="none" pointer-events="fill"`. One delegated `pointerdown` listener on the layer.
4. `<svg class="glow">` — a single copy of the currently highlighted path. The
   `drop-shadow()` goes on the **`<svg>` root**, never on the path inside it:
   the root is `RenderReplaced` → `RenderLayerModelObject` and can composite,
   while an SVG child cannot and would fall back to WebKit's CPU blur — the
   exact thing this layer exists to avoid. Promote and un-promote around use;
   a full-screen composited layer costs about 12.6 MB on a 2048x1536 iPad.
   The glow is for single selection only: never render it during a
   `highlightMany` wave, where rewriting a 22,000-character path 28 times in
   two seconds is a main-thread re-parse plus re-blur each time.

`pointer-events: fill` is the important detail: it sets `canHitStroke=false`, skipping `CGPathCreateStrokedPath` on a several-thousand-point path. It also sets `requireFill=false` and `requireVisible=false`, so a path with no fill and no stroke is still hit-testable at zero rasterisation cost.

Small states need an explicit circle pin, because their real shapes are
smaller than a child's fingertip. Two details, both established by measurement:

**Select them by inscribed radius, not bbox area.** Puducherry's bbox is 5.1x
Punjab's while its land is four scattered enclaves; Andaman & Nicobar and
Lakshadweep fail the same way. The generator emits `r`, the radius of the
largest circle that fits inside the shape, and pins where `r` is small.

**Size each pin individually**, as `min(104px-equivalent, ½ × distance to the
nearest other pole)`. A uniform radius is both too small where there is room
and too greedy where there is not. Measured: Andaman & Nicobar has 203 units
of clearance and Lakshadweep 77, so a genuine 104px target is *free* for
exactly the two territories a child cannot otherwise find. Only Delhi (16.0
units from Haryana's pole) and Chandigarh (19.8) are truly impossible — and a
uniform r=22 over-serves those two at the cost of 24.5% of Haryana's interior.

Place the pin at the **pole of inaccessibility**, not the centroid: three
territories have centroids outside their own shape.

**Snap near misses.** About 1.15% of interior points fall in gaps between the
simplified hit outline and the visible art and resolve to nothing, which a
child reads as the map ignoring them. If a tap resolves to the svg root, pick
the nearest pin within roughly 60 CSS px. WCAG 2.5.8 permits this explicitly
through its Essential exception for map pins. A tap in the open sea must
still pick nothing.

## Task 6: The camera

**Files:**
- Create: `src/map/camera.ts`, `src/lib/cheapMode.ts`
- Test: `src/map/camera.test.ts`, `src/lib/cheapMode.test.ts`

**Interfaces:**
- Consumes `geo.json`'s `viewBox` and per-place `bbox`.
- Produces:
  - `frame(bbox, viewBox, padding): { scale: number; x: number; y: number }` — pure maths, the transform that brings `bbox` to fill `viewBox`.
  - `flyTo(stage: HTMLElement, svg: SVGSVGElement, target: Bbox, opts): Promise<void>` — animates and then commits.
  - `isCheap(): boolean`.

**The transform-then-commit sequence, which is the whole point of this task:**

1. Compute `frame(target)`.
2. Set `stage.style.willChange = 'transform'`.
3. Animate `stage.style.transform` to `translate(...) scale(...)` over 350–450 ms with a gentle ease.
4. On completion, in one frame: set the SVG's `viewBox` to the target rect, set `stage.style.transform = ''`, and clear `willChange`.

The animation is compositor-only, so it holds 60 fps. The commit costs one expensive frame instead of twenty-four, and it re-rasterises at the new scale — which is the only cure for WebKit bug 27684, where a composited layer keeps its pre-animation rasterisation and looks soft for the whole zoom.

`willChange` is added and removed around the animation rather than left on: a full-screen composited layer is about 12.6 MB on a 2048×1536 iPad, and WebKit drops tiles under memory pressure, which shows up as white flashes.

**Motion facts verified against the installed 13.1.1 — use these exactly:**

- Import from **`motion/react`**. Not `framer-motion` (the internal implementation package) and not `motion/react-client` (the RSC build).
- `<motion.path>`, `<motion.g>`, `<motion.circle>` all work. Animating `x`/`y`/`scale` compiles to `style.transform` plus `transform-box: fill-box`.
- **But do not use `<motion.g>` for anything large or map-wide** — see the Global Constraints. It is fine for a small symbol of a few dozen points; it is not fine for the 36-path map.
- Draw-on is `initial={{ pathLength: 0 }} animate={{ pathLength: 1 }}`. Motion sets `pathLength="1"` and drives unitless `stroke-dasharray`/`stroke-dashoffset` itself. Do not call `getTotalLength()`.
- Never use `attrX`/`attrY`/`attrScale` — those write literal SVG attributes and force re-layout.
- `layoutId` is a **silent no-op on SVG**. If a shared-element morph is ever wanted, overlay an absolutely-positioned HTML `<div>` with `layoutId` over the shape's bbox and morph that instead.
- Respect reduced motion with `useReducedMotionConfig()`, not `useReducedMotion()` — the latter reads the device once and does not honour `MotionConfig`.
- Wrap the app in `<MotionConfig reducedMotion="user">`.

**The eleven symbols.** Each is a small hand-drawn SVG, deliberately simple and flat, in the palette from `base.css`. They animate in over 400–600 ms and hold. `outline` is the exception: it draws the India silhouette with `pathLength` and is skipped entirely in cheap mode, because dash-stroking a complex path per frame is the single most likely thing to drop frames on an A8X.
